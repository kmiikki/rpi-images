# Scientific Reporting and Document Generation

GENERAL, HOME and AALTO include reporting in their existing Scientific Python
3.14 environment at `/opt/lab314`. ReportLab generates PDFs with styled text,
tables, headers, footers and bookmarks. pypdf reads, checks and merges PDFs.
Jinja2 renders HTML templates. Matplotlib can save raster and vector figures,
and Plotly can embed an interactive chart together with its JavaScript.

Once the packages are installed, report generation works offline and from SSH
or a headless job. The examples run independently of Chromium, QtWebEngine,
a desktop keyring, Office, LaTeX and external services. Run them in a directory
where you can write the output files.

## Generate a PDF and inspect it

```bash
/opt/lab314/bin/python - <<'PY'
from pathlib import Path

from matplotlib import get_data_path
from pypdf import PdfReader
from reportlab.lib.pagesizes import A4
from reportlab.pdfbase import pdfmetrics
from reportlab.pdfbase.ttfonts import TTFont
from reportlab.pdfgen import canvas

font = Path(get_data_path()) / "fonts/ttf/DejaVuSans.ttf"
pdfmetrics.registerFont(TTFont("DejaVuSans", str(font)))
report = canvas.Canvas("report.pdf", pagesize=A4)
report.setFont("DejaVuSans", 14)
report.drawString(48, 780, "Mittaustulokset · Åbo och Hämeenlinna")
report.save()
print(PdfReader("report.pdf").pages[0].extract_text())
PY
```

## Generate HTML with an offline interactive chart

```bash
/opt/lab314/bin/python - <<'PY'
from pathlib import Path

from jinja2 import Environment
from plotly import graph_objects as go

chart = go.Figure(go.Scatter(x=[1, 2, 3], y=[17, 20, 18]))
template = Environment(autoescape=True).from_string(
    '<!doctype html><html lang="en"><head><meta charset="utf-8">'
    '<title>{{ title }}</title></head><body><h1>{{ title }}</h1>'
    '{{ chart | safe }}</body></html>'
)
html = template.render(title="Temperatures in Åbo",
                       chart=chart.to_html(full_html=False, include_plotlyjs=True))
Path("report.html").write_text(html, encoding="utf-8")
PY
```

Only mark HTML generated by trusted code as safe. A JavaScript-capable browser
is required to interact with the finished chart. The embedded Plotly.js bundle
adds several megabytes per HTML file. Maps, remote fonts, CDN resources and
other external data may still require connectivity. Embed fonts that cover
the scripts you need. Text extraction from scanned PDFs requires separate
OCR. Browser-based HTML-to-PDF conversion and Plotly static-image export are
outside the reporting check.

## Verify and maintain the packages

From `trixie/base/install`, run the reporting test on its own.

```bash
/opt/lab314/bin/python -IB check_lab314.py --prefix /opt/lab314 --reporting-only
```

Expect PDF and HTML PASS lines followed by the versions. The test writes its
reports, charts and Matplotlib cache into a temporary directory and removes it
when it finishes. The normal `verify_rpi_lab314.sh --science-only` check also
runs the reporting test and checks package metadata, imports, ownership-sensitive
scientific components and dependency consistency.

Existing lab314 installations can reconcile missing defaults through normal
setup. Explicit component updates use the existing review procedure. Preview
a targeted repair with this command, then review and approve the repair using
the same command without `--plan`.

```bash
sudo bash setup-rpi.sh --manage --action repair --component lab314 \
  --package reportlab --package pypdf --package jinja2 --plan
```

See [lab314 maintenance](lab314-maintenance.md) for ownership, backups, updates
and recovery. The historical snapshot has its original verification contract.
